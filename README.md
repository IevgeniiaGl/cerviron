# CERVIRON

Двуязычный Статический двуязычный сайт продукта CERVIRON.

- По умолчанию открывается румынская версия: `ro/index.html`.
- Русская версия находится в `ru/`.
- Стили уже готовы в `css/style.css`; сборка, SCSS и внешние зависимости не требуются.
- Изображение продукта: `img/cerviron_img.webp`.

## Структура классов

Вёрстка использует BEM без препроцессоров: самостоятельные блоки (`.header`, `.nav`, `.hero`, `.card`, `.product`, `.footer`), их элементы (`.hero__image`, `.header__inner`, `.card__number`) и модификаторы (`.button--primary`, `.nav--open`). Класс `.container` — только вспомогательный класс для ограничения ширины контента.

Для просмотра откройте `index.html` через любой статический сервер или в браузере.

## Вставки через SSI (папка `includes/`)

Страницы подключают общие фрагменты через Apache SSI (`mod_include`). В `.htaccess` для этого включены `Options +Includes` и `AddOutputFilter INCLUDES .html`. Прямой доступ к `/includes/` закрыт (403), при этом сами вставки работают.

Папка `includes/` **не хранится в git** (см. `.gitignore`). На сервере её нужно создать вручную один раз:

| Файл | Куда вставляется | Формат |
|---|---|---|
| `includes/head.html` | в `<head>` каждой страницы, сразу после `<meta name="viewport">` | HTML: код Google Tag Manager (`<script>`) и других сервисов. Можно оставить только комментарий. |
| `includes/body.html` | сразу после `<body>` каждой страницы | HTML: `<noscript>`-часть Google Tag Manager и т.п. Можно оставить только комментарий. |
| `includes/site-url.txt` | в `canonical`, `hreflang`, `og:url`, `og:image`, `twitter:image` и JSON-LD | Адрес сайта без слеша в конце и **без переноса строки в конце**, например `https://cerviron.punct.one` |

Создать `site-url.txt` без переноса строки: `printf 'https://cerviron.punct.one' > includes/site-url.txt` (не `echo`).

Если какого-то файла нет, страница всё равно открывается: директива `<!--#config errmsg="" -->` скрывает сообщение об ошибке SSI. Но без `site-url.txt` абсолютные ссылки в мета-тегах будут неполными.

**При заливке по FTP папку `includes/` на сервере не перезаписывать и не удалять.**

Если хостинг не разрешает SSI через `.htaccess`, сайт будет отдавать ошибку 500. Тогда уберите из `.htaccess` `+Includes` и строку `AddOutputFilter INCLUDES .html` и попросите хостинг включить `mod_include`.

Локально (без Apache) SSI-директивы не выполняются: они остаются HTML-комментариями, поэтому ссылки в мета-тегах при локальном просмотре неполные — это нормально.
